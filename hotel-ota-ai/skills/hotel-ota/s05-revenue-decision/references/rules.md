# S5 智能收益决策规则

## 核心原则

- S5 调整对象是 OTA 商品当前原卖价，也就是交给 S6 dry-run 的商品价格。
- S5 不读取价格上下限配置，不将其作为候选门禁、目标价边界、质量标记、阻断原因或业务展示内容。
- 候选价只由经营证据、S5 算法幅度和单次变动硬上限确定。
- 单次候选变动绝对值不得超过 10%。
- S5 只生成候选或人工预览，不创建审批、不写 outbox、不调用渠道调价接口。

## 核心输入字段

### 商品和范围

- `hotel_id`
- `target_stay_date`
- `channel`
- `ota_product_id`
- `room_type_id`
- `current_price`
- `price_editable_flag`
- 商品状态与可信映射证据

### 房型经营证据

- S15 房型历史成交价中位数、P20、P80
- S15 全局精确小时网格覆盖率、当前决策小时精确样本、覆盖率与成熟度（仅用于输出置信度，不作为涨价、降价、维持或人工预览的门槛）
- S16 房型销售进度偏差
- 房型总库存、已售和剩余库存比例

### 市场和流量证据

- S16 最终市场热度结果
- S16 `comparison_allowed`
- S16 预计全天大盘订单及历史完整日基线
- 浏览趋势
- 二转趋势及样本有效性
- S7 酒店级同行聚合背景

### 收益展示证据

- 商品原卖价
- 平台佣金率
- 全部有效活动系数
- 活动有效时间和商品匹配关系

## 价格和收入口径

- 调价对象：商品原卖价。
- 预计酒店收入：`商品原卖价 ×（1−佣金率）× 全部有效活动系数连乘`。
- 预计酒店收入不含用户券，只供运营查看，不参与调价写入或审批。
- PMS 房型成交历史价用于判断当前商品到手收入是否偏高或偏低，不作为渠道写入价。
- 同行聚合仅作为酒店级背景，不代表同一商品精确竞品比价。

## 市场热度口径

S5 必须直接使用 S16 的最终市场结果，不得自行重算。

盘中采用 S16 线性预计全天口径：

```text
预计全天大盘订单 = 当前累计大盘订单 ÷ 当天已过时间比例
大盘热度 = 预计全天大盘订单 ÷ 历史完整日大盘订单基线
```

状态门槛：

```text
热度 < 0.90  → cold，市场不冷 = 否
0.90 ≤ 热度 < 1.10 → normal，市场不冷 = 是
热度 ≥ 1.10 → hot，市场不冷 = 是
```

只有 S16 明确返回 `comparison_allowed=true` 时，市场证据才可进入 S5 规则。

## 正式涨价规则

必须同时满足：

1. 房型销售进度领先至少 `+8pp`；
2. 剩余库存比例不高于 `30%`；
3. S16 市场不冷；
4. 商品可售、可编辑、映射可信。

涨价幅度根据领先程度和库存紧张度在约 `3%～5%` 内计算，并受 `10%` 单次硬上限约束。

## 正式降价规则

必须同时满足：

1. 房型销售进度落后至少 `8pp`；
2. 剩余库存比例不低于 `50%`；
3. 流量健康；
4. 二转偏弱且样本有效；
5. 商品到手收入相对房型历史成交价显著偏高；
6. 商品可售、可编辑、映射可信。

降价幅度根据落后程度和价格偏高程度在约 `5%～8%` 内计算，并受 `10%` 单次硬上限约束。

市场偏冷不会阻止降价；市场不冷是涨价的强前提。

## S15 时间证据

- 全局小时网格覆盖、当前决策小时样本和成熟度只标记证据强度：`formal`、`limited` 或 `weak`；
- 不以全局覆盖率、当前小时样本数或成熟度阻断、触发或改变 S5 的涨价、降价、维持或人工预览结论；
- 执行时的实时价格、商品映射、权限与写入安全复核由 S6 负责。

## 维持和阻断

以下情况维持当前原卖价：

- 销售进度处于维持区间；
- 涨价时市场热度低于 `0.90`；
- 库存松紧程度不满足方向规则；
- 流量、二转或价格偏高证据不满足降价规则；
- 商品不可售、不可编辑或映射不可信；
- S16 市场结果不可比或缺失。

不得出现与价格上下限配置有关的 blocker、质量标记或解释。

## 数据新鲜度与降级

- 业务日期必须与目标入住日一致。
- 价格观察需要保留业务日和抓取时点。
- `stale`、`missing_date`、`demo_data`、`sample_data`、`manual_chat` 只能生成演示或低置信度结果，不能形成正式候选。
- 缺少核心证据时返回 `data_gap` 或 `partial`，不得把缺失值编造成 0。

## 角色权限

- `admin`、`owner`、`operator` 可以触发收益建议。
- `frontdesk` 不可触发正式收益建议；应提示联系运营或老板。
- `guest` 不触发 S5，不读取价格、出租率或收益证据。
- 真实执行必须交给 S6，并遵守 S6 的执行契约与审批边界。

## 输出结构

确认输出：

- `current_price`
- `candidate_price`
- `actual_change_pct`
- `price_action`
- 房型销售与库存证据
- S16 市场和流量证据
- S15 时间证据
- 预计酒店收入
- `blocked_reason`
- `eligibility`
- `handoff_to`

S5 输出不得包含价格上下限配置、相关状态或相关决策字段。

## 禁止事项

- `treat_demo_data_as_real_today_data`
- `create_formal_approval_from_demo_or_stale_data`
- `bypass_data_gate_or_approval_boundary`
- `write_channel_price_directly`
- `call_live_execution_without_S6`
- `recompute_s16_market_heat_inside_s5`
- `read_or_apply_configured_price_bounds_in_s5`
- `render_configured_price_bounds_in_s5_reply`

## 测试要求

至少覆盖：

- 缺少价格上下限配置时仍能按业务证据形成候选；
- 当前价格高于旧配置顶价时不会形成“没有涨价空间”阻断；
- 当前价格低于旧配置底价时不会形成“没有降价空间”阻断；
- 候选载荷、决策引用和业务回复均不包含相关字段或文案；
- 单次算法变动仍不得超过 10%；
- S15 时间证据只影响置信度展示；S16 市场门槛、商品映射与可编辑性继续生效。
