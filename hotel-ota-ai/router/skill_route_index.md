# 飞书自然语言 Skill 路由索引

> 交付前 P0 稳定规则。本文只定义普通自然语言问题的主 Skill 所有权，不定义算法、数据口径、权限或执行能力。
>
> 对普通飞书自然语言路由，本文件的 ownership 规则优先于 `AGENTS.md` 中历史性的 Skill 示例和 Scenario 名称。权限、数据真实性和执行边界仍以 runtime / contracts / `AGENTS.md` 为准。

## 1. 总规则

- **ROLE / BIND / CFG 控制面写操作及其确认/取消不属于普通 Skill 路由。** 任命、授予、撤销、直接更换 `owner/operator/frontdesk`，以及 `确认/取消 ROLE-*`、BIND/CFG 申请/确认/取消，必须在读取本索引、S1 Skill 或 Scenario 之前由控制面 Fast Path 直接进入 `feishu-route`；不得先路由到 S1 再找工具。
- 普通业务问题优先选择 **一个主 Skill**，命中后不再因为辅助证据词重新搜索其他 Skill 或 Scenario。
- **单事实查询采用 20 秒响应预算**：用户只问一个金额、数量、状态、比例、排名或时间点事实时，先执行主 Skill 的一次受控读取。若主 Skill 已能可靠回答，直接返回；若主 Skill 明确缺字段、缺时间粒度或没有对应事实，可在不切换其他 Skill/Scenario 的前提下尝试 **一次受控只读 SQL factual fallback**。
- factual fallback 只用于数据库事实查询，不重新实现业务算法。允许的查询必须是当前酒店范围内的只读查询；写操作、跨酒店查询、敏感字段、危险 SQL、业务决策、建议、审批、配置修改和执行动作不得进入此 fallback。
- **20 秒内不能形成可靠答案就结束当前请求**，不要继续静默搜索或漫游。回复用户：`这个问题需要进一步查询业务数据库，可能会比普通查询慢一些。回复「继续查询」我再继续。` 这表示当前请求已经结束，不得表述成“正在后台查询”或“请稍等”。
- 用户在同一对话中回复 `继续查询` 时，沿用上一条待深入查询的问题及当前酒店上下文继续；第二阶段仍只允许受控只读查询，失败或仍无可靠数据时直接说明数据缺口并结束，不得再次无限搜索 Skill/Scenario。
- Skill 可以按既有 dependency contract 读取确定性上游事实；这不等于重新路由。但单事实查询如果当前 Skill 已明确“不具备该粒度/字段”，不得为了凑答案启动其他业务 Skill 依赖链；只可使用上述受控 factual fallback。
- 只有用户明确要求“完整、综合、全盘、一起分析、一整套、完整经营分析”等多能力流程时，才考虑 Scenario。
- “今日日报 / 昨日日报 / 今天日报 / 昨天日报 / 今日经营日报 / 昨日经营日报”及“生成/查看”这些日报内容请求固定由 **S2 单 Skill** 负责；不得因为日报中包含流量、进度、健康度等字段而升级为 S14、S16、S9 或 Scenario。
- S14 已进入退役阶段：**不作为新的普通自然语言路由候选，也不得通过 SQL fallback 恢复或拼装 S14**。现有显式 legacy 入口暂保留兼容，本次不物理删除 runtime。
- S8 只按当前真实能力理解为推广通数据展示；推广是否值得继续由 S10 判断。

## 3. 冲突时按“最终要回答什么”选主 Skill

- `把张三换成前台` / `将张三设为运营` / `撤销张三的角色` / `确认 ROLE-...` → **控制面 Fast Path**；直接 `feishu-route`，不进入 S1、其他 Skill 或 Scenario。
- `我的权限是什么` / `owner 能不能任命前台` / `当前酒店有哪些角色` → **S1**；这是权限/角色查询或解释，不是控制面写操作。
- `生成昨日日报` / `昨日日报` / `今日日报` → **S2**；日报是经营快照内容请求，只返回 S2 事实视图，不拼装 S14/S16/S9 综合诊断。
- `生成今日日报，重点看流量和销售进度` → **S2**；“流量/进度”只是日报展示字段，不改变主 Skill。
- `今天要不要调价，大盘怎么样？` → **S5**；大盘是调价证据，属于业务决策，不允许通用 SQL fallback 替代 S5 算法。
- `为什么今天卖得慢，是不是价格太高？` → **S16**；价格只是候选原因，属于业务诊断，不允许通用 SQL fallback 重写 S16 判断。
- `市场怎么样，会不会影响销售？` → **S4**；主问题是市场环境。
- `浏览低是不是导致销售落后？` → **S16**；主问题是销售归因。
- `今天浏览、一转、二转怎么样？` → **S16**；属于当日动态诊断。
- `美团和携程近30天漏斗对比` → **S9**；属于明确专项漏斗分析。
- `推广总共花了多少钱` / `推广费用多少` / `推广曝光和点击多少` → **S8**；这是推广通事实查询，不升级为 S10/S11。
- `今天的门店推广总共花了多少钱` → **S8 先检查固定源**；当前 S8 固定源 `meituan_ota_promotion_performance_30d` 只有近 30 天周期快照，不能把周期累计拆成今日单日值。此问题属于事实查询，因此可在 20 秒预算内尝试一次受控只读 SQL 补查；20 秒内仍不能可靠回答则立即结束本轮并提示用户回复 `继续查询`，不得继续横向搜索其他 Skill。
- `近30天推广总共花了多少钱` → **S8**；按 S8 固定 30 天数据源读取并展示。

## 4. Scenario 入口

普通的“今天经营怎么样”“今日日报”“昨日日报”“今天要不要调价”“差评怎么样”“客户订单分析”不得仅因为 Scenario 名称相似或回答中包含多个展示字段就升级为 Scenario。

只有明确多能力组合请求才读取 `router/scenario_router.yaml` / `architecture/scenario_chain_registry.json`，例如：

- `完整分析今天经营、市场、销售进度、流量和价格`
- `给我做一次全盘经营分析`
- `综合考虑市场、进度、竞对和价格给完整收益分析`

本索引不改变现有 Scenario runtime；只降低普通问题被 Scenario 抢入口的概率。
