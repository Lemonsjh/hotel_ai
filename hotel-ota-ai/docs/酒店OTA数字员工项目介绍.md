# 酒店 OTA 数字员工

## 项目介绍

### 1. 项目定位

酒店 OTA 数字员工是一套基于 OpenClaw Runtime 构建的酒店运营协同系统。它通过飞书接收运营指令，在可信身份、酒店范围和数据权限校验后，读取 PMS 与 OTA 真实经营数据，形成可解释的经营事实、建议和受控执行任务。

它不是通用聊天机器人，而是服务于收益、渠道、推广和口碑运营的数字化工作台。系统将“查数、判断、建议、确认、执行、回查”拆分为可审计的闭环，帮助酒店团队缩短日常经营决策的响应时间。

### 2. 解决的业务问题

- PMS、OTA、推广和评价数据分散，经营人员需要在多个后台之间重复切换。
- 调价、推广和评论回复常依赖人工经验，缺少统一的证据、权限和留痕。
- 运营团队难以快速区分酒店级同行指标、月度流失背景与商品级精确比价。
- 数据缺失或口径不一致时，容易把不完整数据误作经营结论。

### 3. 核心能力

| 业务域 | 可提供的能力 | 主要输出 |
| --- | --- | --- |
| 经营运行 | 实时房态、出租率、ADR、RevPAR、房型状态 | 经营运行快照 |
| 销售与收益 | 历史销售基准、销售进度、大盘热度、调价候选 | 收益建议、调价预览 |
| 渠道与竞态 | 自有商品、同行聚合、竞争圈、月度流失背景 | 竞态监控、市场证据 |
| 推广经营 | 推广表现、观测 ROAS、获客成本、投放建议 | ROI 分析、推广建议 |
| 口碑运营 | 评论概览、未回复评论、回复草稿与待执行任务 | 口碑诊断、回复任务 |
| 综合诊断 | 汇总可用模块事实与数据缺口 | 综合运营诊断 |

### 4. 使用方式

运营人员可在飞书中直接 @酒店数字员工提问，例如：

- “今日经营情况”
- “有哪些可调价商品”
- “对商品 ID 进行调价 dry-run”
- “推广建议”
- “最近 3 天新增评论”
- “S7 竞态监控”

系统先按当前群聊或私聊绑定的酒店和已验证身份处理请求，再输出对应业务结果。没有真实数据时返回数据缺口，不以演示或推测内容替代正式结论。

### 5. 调价与执行闭环

1. 读取真实商品价格、房型经营、销售进度和市场证据。
2. S5 生成只读收益候选，说明建议净收、房型历史成交参考及触发原因。
3. S6 对指定 OTA 商品进行 dry-run，重新校验商品身份、当前价、数据新鲜度和单次涨跌幅限制。
4. 用户使用确认令牌确认后，系统写入待执行调价任务。
5. 渠道插件拾取任务、执行渠道操作并进行平台价格回查。

系统不把房型级经营参考误写为商品级竞品比价；同一房型存在多个 OTA 商品时，必须精确指定 `ota_product_id`，避免团购、钟点房和挂牌商品被错误覆盖。

### 6. 竞态与市场判断原则

S7 将竞态事实划分为四个可比等级：精确商品、同行聚合、月度流失背景和仅本店事实。当前没有精确竞品商品集合时，系统不会输出“某房型比某竞店贵多少”的结论。

同行引流价、浏览人数、支付订单等指标仅表达酒店级或同指标位置；月度流失订单、竞争圈和竞店最低价仅作为平台归因背景，不等同于实时房型价格因果。

### 7. 数据架构与多酒店隔离

每家酒店使用独立数据库。`hotel_id` 用于飞书会话绑定、身份授权、数据路由和一致性校验；酒店展示名称只用于界面显示或受控兼容，不作为跨酒店取数依据。

系统主要读取 PMS 经营数据、OTA 商品价格、OTA 经营指标、活动、推广表现、评价和流失背景等数据表。读取时优先使用精确酒店范围和平台范围；缺少酒店标识的历史表仅允许受控只读诊断，不允许跨酒店借数。

### 8. 权限、安全与审计

- 每次飞书业务请求先在 SQLite Active Auth 中校验可信身份、群聊绑定与酒店角色。
- 查询、建议、dry-run、确认和任务写入分层控制；没有必要权限时默认拒绝。
- 生产环境禁止回退到演示数据；数据缺失、过期或表结构漂移时明确标注。
- 调价、评论回复等写入动作需经过范围校验、幂等控制、确认流程和任务回读。
- 对外回复不展示数据库连接信息、密钥、住客行级隐私数据或渠道内部敏感字段。

### 9. 交付价值

- 将分散的数据查询收敛到飞书运营入口。
- 用统一口径呈现经营事实、市场证据和数据限制。
- 将经验型运营动作转化为可复核、可确认、可追踪的任务流程。
- 支持酒店在不降低安全边界的前提下提升收益、渠道、推广和口碑运营效率。

### 10. 后续建设方向

- 持续补齐 OTA 商品级竞品采集，提高精确比价能力。
- 完善渠道插件回查和异常闭环，提高写入任务的可验证性。
- 扩展更多酒店独立数据库接入，并标准化酒店上线校验流程。
- 逐步完善数据采集覆盖、历史基准成熟度和推广增量效果评估。

### 11. 能力边界说明

- 没有精确竞品商品价格时，不生成房型级竞品价差。
- 平台归因 ROAS 不等于净利润或增量 ROI。
- PMS 房型历史成交价可作为经营参考，但不能直接等同于 OTA 商品挂牌价的商品级历史。
- 系统输出建议不等于自动执行；写入类动作必须经过相应的安全与确认流程。
