# S15/S16 用户输出与术语合同

## 1. 目的

本合同约束飞书、CLI 摘要和智能体面向业务用户的 S15/S16 输出。确定性算法的完整原始字段仍可保留在本地受信调试结果中，但生产飞书正文不得直接抛出内部字段名、英文枚举、表名或算法版本。

## 2. 核心术语

| 内部字段 | 面向业务用户的名称 | 说明 |
|---|---|---|
| `committed_sold` | 承诺已售房量（间） | `total_rooms-available_rooms+overbooking_rooms`；是销售承诺口径，不等同于物理在住房 |
| `occupied_rooms` | 物理在住房（间） | 仅作房态背景，不能和承诺已售混为一个数字 |
| `effective_target_room_nights`，来源为 `historical_inferred_target` | 历史同类日参考最终已售房量（间） | 来自同类历史营业日最终已售房量中位数；不是人工下达目标，不简称“目标间夜” |
| `effective_target_room_nights`，来源为批准目标 | 今日批准目标已售房量（间） | 仅在确有人工批准目标时使用该名称 |
| `capacity_progress` | 容量销售节奏 | 承诺已售房量 ÷ 可售总房量 |
| `target_completion` | 参考最终已售完成节奏 / 批准目标完成节奏 | 根据目标来源选择名称；不能与容量销售节奏合成一条线 |
| `room_gap` | 当前比同时点参考多售/少售房量（间） | 正数为超前，负数为落后 |
| `remaining_target_gap` | 距离参考最终已售量仍差房量（间） | 可为负，表示已经超过参考值 |

## 3. 订单数边界

订单数、已售房量和间夜是三个不同业务量。除非真实订单源提供订单计数，否则：

- 不输出“目标订单”；
- 不输出“实际订单”；
- 不使用“1 单约等于 1 间夜”；
- 不将房量差额转换成订单差额。

## 4. S15 必须展示的内容

生产飞书的 S15 正文至少包含：

1. 目标日、参考最终已售房量及其来源；
2. 全店容量销售节奏与参考最终已售完成节奏两条基准；
3. P25–P80 常见区间、样本数和逐时点成熟度；
4. canonical 房型层两条节奏摘要；
5. 房型历史成交价基准；
6. 美团与携程各自的浏览和转化基准；
7. 当前无法形成的市场订单、市场份额等对象及原因；
8. 24 小时采集覆盖与缺失小时。

不得只显示一个“分时目标曲线”。

## 5. S16 必须展示的内容

生产飞书的 S16 正文至少包含：

1. 当前承诺已售房量、可售总房量和参考最终已售房量；
2. 全店容量销售节奏偏差；
3. 全店参考最终已售完成节奏偏差；
4. 两条线的 P25–P80、百分点差、同时点应售房量和间数差；
5. 每个房型的两条偏差、最终参考差和成熟度；
6. 房型快慢数量、滞后目标占比和结构标签；
7. 使用批次距请求时点的分钟数，以及房型范围是否完整。

不得只输出一个 `ahead/behind` 结论。

## 6. 中文化与隐藏规则

生产飞书中不直接展示：

- `historical_inferred_target`、`object_level`、`on_track_or_ahead` 等内部枚举；
- `formula_version`、`policy_version`、`baseline_revision`、`report_revision`；
- MySQL 表名、字段名、DSN、SQL；
- `runtime_command`、`dependency_runs`、内部调试步骤；
- “先试了什么、重跑了几次”等执行过程。

这些信息仅允许在本地受信调试输出中查看。

## 7. 时间口径

- 未显式传入 `as_of` 时，使用酒店本地当前时间；
- 不得默认当天 `23:59:59`；
- 用户显式传入 `HH:MM` 时，与目标业务日期组合；
- 当前 forecast 快照必须不晚于 as-of，并显示实际使用批次距请求时点的分钟数；
- 快照超过允许间隔时返回数据时效缺口，不修改 as-of 以迁就数据。

## 8. 性能合同

生产飞书中的普通 `s15`、`s16` 请求：

- 只执行一次真实业务能力；
- 不先跑 demo 节点；
- 不为 S16 再执行 S2 能力结果；
- S16 直接读取共享销售进度当前事实，并消费已保存的 S15 基准；
- 不为“核对结果”自动重复运行同一能力；
- 执行耗时记录在服务日志中，但不把调试过程回复给业务用户。

显式包含“演示/demo”时，才允许走 demo 节点。

## 9. 结论边界

S15/S16 只描述基准、进度和结构：

- 不因当前超前就断言“大概率满房”；
- 不以“结果没问题，可以放心用”覆盖成熟度或数据缺口；
- 不在 S16 中直接生成调价、推广或其他执行动作；
- 对低成熟度结果明确标注仅作趋势参考。
